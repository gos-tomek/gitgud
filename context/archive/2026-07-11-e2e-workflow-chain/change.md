## Notes

<!-- Free-form notes for this change: links, ad-hoc context, decisions that don't belong in research/frame/plan. -->

- 2026-07-30: Phase 1 manual verification surfaced that `wrangler dev` cannot run this project's `src/worker.ts` at all (unresolvable Astro/Vite virtual modules). Researched and replanned: the local E2E runtime is `astro dev` + `CLOUDFLARE_VITE_WRANGLER_CONFIG_PATH=./wrangler.e2e.jsonc`, not a separate `wrangler dev` process. See `research.md` and the corrected `plan.md`/`plan-brief.md`.
- 2026-07-31: Phase 2 sync-chain.spec.ts surfaced that the sync Workflow was silently broken end-to-end: `get_user_github_pat`, `get_unclassified_root_comments_for_board`, and `batch_update_pr_sizes` were never granted `EXECUTE` to `service_role` in their migrations (only `authenticated`). Production already carried the `get_user_github_pat` grant applied out-of-band; the other two were real, previously-unnoticed gaps. Fixed via three additive migrations (commit 3a816f0). Also found and fixed a local-only environment issue: the local `supabase` CLI devDependency (`^2.23.4`) had drifted to 2.109.0, which resolves a Postgres image that doesn't bootstrap `service_role`'s default table grants — confirmed via Supabase's own docs that this is a platform regression, not an intentional convention change. Pinned to `2.101.0` to match CI's `supabase/setup-cli@v2` version.
- 2026-07-31: PR #95's `test-integration` CI job failed with `duplicate key value violates unique constraint "github_pull_requests_pkey"` — pre-existing bug, unrelated to this change's phases. Root cause: `tests/helpers/seed.ts` (`seedTwoBoards()`) and `tests/integration/account-deletion.test.ts` both derive `const ts = Date.now()` and use the raw value as the `github_pull_requests` bigint PK with no offset; when Vitest runs both in parallel workers within the same millisecond, they collide. `board-settings.test.ts` and `pat-leak.test.ts` carry the identical latent pattern (with offsets that happened not to collide this run). Fixed all four by adding random jitter to the base `ts` (`Date.now() * 1000 + Math.floor(Math.random() * 1000)`). See "Never use a raw Date.now() as a literal bigint PK in test fixtures" in `lessons.md`.
- 2026-07-31: Re-ran CI after the above fix; `test-integration` failed again, this time in `e2e-config-boot.test.ts` (added by this change's Phase 1) with "file does not exist in the optimize deps directory" then, on a second local repro attempt, `EADDRINUSE` on the inspector port. Root cause: this test and the pre-existing `pat-leak.test.ts` both spawn a real `astro dev` child process via `tests/helpers/astro-server.ts`, and Vitest runs them in parallel — two concurrent `astro dev` instances race on the shared Vite SSR dep-optimizer cache and the Cloudflare Vite plugin's inspector-port auto-detection, both of which use an unlocked probe-then-bind sequence. Genuine race condition (passed on the first CI run, failed on the second with no code change in between). Fixed by giving each spawned instance an isolated `VITE_CACHE_DIR` (keyed by port) and disabling the inspector port entirely for test-spawned servers (`CLOUDFLARE_VITE_DISABLE_INSPECTOR`) — verified with repeated concurrent local runs. See "Concurrent astro dev spawns racing on shared Vite/Miniflare state" in `lessons.md`.
